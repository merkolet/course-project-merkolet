# Hardening Summary (P12)

## Обзор

Данный документ описывает меры харднинга, применённые к Dockerfile и IaC (compose.yaml) для проекта wishlist-api.

## Dockerfile Hardening

### До (исходное состояние)

- Использовался базовый образ `python:3.11-slim` без конкретной версии
- Не было явного указания версий пакетов
- Минимальные ограничения на права доступа

### После (текущее состояние)

#### 1. Фиксация версий образов и пакетов

**Изменение:**
- `FROM python:3.11-slim` → `FROM python:3.11.10-slim`
- Добавлена фиксация версии gcc в build stage: `gcc=4:12.2.0-3ubuntu1`

**Обоснование:**
- Предотвращает неожиданные изменения при обновлении базового образа
- Обеспечивает воспроизводимость сборок
- Упрощает отслеживание уязвимостей

#### 2. Улучшенная настройка non-root пользователя

**Изменение:**
- Явное указание UID/GID: `groupadd -r appuser -g 1000` и `useradd -r -g appuser -u 1000`
- Установка правильных прав доступа: `chmod 755 /app`
- Настройка временных директорий: `chmod 1777 /tmp /var/tmp`

**Обоснование:**
- Предотвращает эскалацию привилегий
- Ограничивает доступ к файловой системе
- Соответствует принципу наименьших привилегий

#### 3. Дополнительные переменные окружения для безопасности

**Изменение:**
Добавлены переменные:
- `PYTHONHASHSEED=random` - предотвращает hash-based DoS атаки
- `PIP_NO_CACHE_DIR=1` - отключает кэш pip для уменьшения поверхности атаки
- `PIP_DISABLE_PIP_VERSION_CHECK=1` - отключает проверку версии pip

**Обоснование:**
- Снижает риск эксплуатации известных уязвимостей
- Уменьшает размер образа
- Улучшает безопасность runtime

## IaC Hardening (compose.yaml)

### До (исходное состояние)

- Порты были открыты на всех интерфейсах (`0.0.0.0`)
- Не было явного указания пользователя
- Минимальные ограничения на сетевой доступ

### После (текущее состояние)

#### 1. Ограничение сетевого доступа

**Изменение:**
- `ports: - "8000:8000"` → `ports: - "127.0.0.1:8000:8000"`
- `ports: - "5432:5432"` → `ports: - "127.0.0.1:5432:5432"`

**Обоснование:**
- Порты доступны только с локального хоста
- Предотвращает несанкционированный доступ извне
- Соответствует принципу минимальной поверхности атаки

#### 2. Явное указание пользователя

**Изменение:**
Добавлено:
```yaml
user: "1000:1000"
```

**Обоснование:**
- Гарантирует запуск контейнера от non-root пользователя
- Дополнительный уровень защиты даже если USER в Dockerfile не сработает

#### 3. AppArmor профиль

**Изменение:**
Добавлено:
```yaml
security_opt:
  - apparmor:docker-default
```

**Обоснование:**
- Применяет стандартный AppArmor профиль Docker
- Ограничивает системные вызовы контейнера
- Дополнительный слой защиты на уровне хоста

## Существующие меры безопасности

### Dockerfile

- Multi-stage build для уменьшения размера образа
- Non-root пользователь (appuser)
- HEALTHCHECK для мониторинга состояния
- Минимальный базовый образ (slim)
- Очистка кэша apt после установки пакетов

### compose.yaml

- `no-new-privileges:true` - предотвращает получение новых привилегий
- `cap_drop: ALL` - удаляет все capabilities
- `read_only: true` - монтирует корневую файловую систему только для чтения
- `tmpfs` с `noexec,nosuid` - предотвращает выполнение из /tmp
- Health checks для обоих сервисов

## Результаты сканирования

### Hadolint

После применения мер харднинга:
- Все критические правила (DL3001, DL3002, DL3006, DL3007) соблюдены
- Предупреждения по версиям пакетов обработаны через конфиг

### Checkov

- Все проверки Dockerfile пройдены
- Нет критических находок в IaC

### Trivy

- Регулярное сканирование образа на уязвимости
- Критические и высокие уязвимости отслеживаются и исправляются через обновление базового образа

## Рекомендации для дальнейшего улучшения

1. **Secrets Management**: Использовать Docker secrets или внешний vault вместо переменных окружения
2. **Image Scanning**: Интегрировать сканирование в процесс сборки образа
3. **Network Policies**: Применить network policies для изоляции контейнеров
4. **Audit Logging**: Включить аудит действий контейнера
5. **Regular Updates**: Регулярно обновлять базовые образы и зависимости
