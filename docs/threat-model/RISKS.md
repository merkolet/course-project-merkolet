# Risk Register (Реестр рисков)

## Обзор
Данный документ содержит реестр рисков информационной безопасности для Wishlist API. Риски оцениваются по вероятности (Likelihood, L) и влиянию (Impact, I) по шкале 1-5, с итоговой оценкой Risk = L × I.

## Шкала оценки

### Вероятность (Likelihood, L)
| Балл | Уровень | Описание |
|---|---|---|
| 1 | Очень низкая | Крайне маловероятно (< 5% в год) |
| 2 | Низкая | Редкое событие (5-25% в год) |
| 3 | Средняя | Возможное событие (25-50% в год) |
| 4 | Высокая | Вероятное событие (50-75% в год) |
| 5 | Очень высокая | Почти неизбежно (> 75% в год) |

### Влияние (Impact, I)
| Балл | Уровень | Описание |
|---|---|---|
| 1 | Минимальное | Незначительные последствия, быстрое восстановление |
| 2 | Низкое | Локальные проблемы, восстановление < 1 дня |
| 3 | Среднее | Заметное влияние на бизнес, восстановление 1-3 дня |
| 4 | Высокое | Серьезное влияние, финансовые потери, восстановление 3-7 дней |
| 5 | Критическое | Катастрофические последствия, репутационный ущерб, > 7 дней |

### Уровень риска (Risk = L × I)
| Значение | Уровень | Действия |
|---|---|---|
| 1-4 | Low | Принять или минимальный контроль |
| 5-9 | Medium | Снизить через контроли |
| 10-16 | High | Активное снижение, обязательные контроли |
| 17-25 | Critical | Немедленные действия, эскалация |

## Реестр рисков

### RISK-001: Отсутствие аутентификации
**Описание**: В текущей версии API отсутствует механизм аутентификации, любой пользователь может читать/изменять/удалять данные любого пользователя.

| Параметр | Значение |
|---|---|
| **Связанная угроза** | S-F1, E-F10 (STRIDE) |
| **Связанные потоки** | F1, F10 (DFD) |
| **Связанные NFR** | NFR-004 (Безопасность данных) |
| **Likelihood (L)** | 5 (очень высокая - API публичен) |
| **Impact (I)** | 4 (высокое - несанкционированный доступ к данным) |
| **Risk Score** | **20 (Critical)** |
| **Стратегия** | **Снизить** (Mitigate) |
| **Владелец** | Backend Team Lead |
| **Срок** | Sprint 5 (2 недели) |
| **Критерии закрытия** | JWT authentication реализован<br>Все endpoints требуют валидный токен<br>Unit тесты покрывают auth flow (≥ 90%)<br>OWASP ZAP baseline без auth bypass findings |

---

### RISK-002: DDoS атака на API
**Описание**: Отсутствие rate limiting позволяет выполнить DDoS атаку, что приведет к недоступности сервиса.

| Параметр | Значение |
|---|---|
| **Связанная угроза** | D-F1 (STRIDE) |
| **Связанные потоки** | F1, F2 (DFD) |
| **Связанные NFR** | NFR-002 (Пропускная способность), NFR-003 (Доступность) |
| **Likelihood (L)** | 4 (высокая - публичный API без защиты) |
| **Impact (I)** | 4 (высокое - полная недоступность) |
| **Risk Score** | **16 (High)** |
| **Стратегия** | **Снизить** (Mitigate) |
| **Владелец** | DevOps Engineer |
| **Срок** | Sprint 4 (1 неделя) |
| **Критерии закрытия** | Rate limiting на LB уровне (100 req/min per IP)<br>Application-level rate limiting (FastAPI middleware)<br>Stress test подтверждает graceful degradation<br>Monitoring alerts на spike traffic настроены |

---

### RISK-003: SQL Injection при миграции на PostgreSQL
**Описание**: При переходе с in-memory на PostgreSQL возможно внедрение SQL injection, если не использовать ORM/prepared statements.

| Параметр | Значение |
|---|---|
| **Связанная угроза** | I-F5 (STRIDE) |
| **Связанные потоки** | F5-F6 (DFD) |
| **Связанные NFR** | NFR-004 (Безопасность), NFR-005 (Валидация) |
| **Likelihood (L)** | 3 (средняя - зависит от качества реализации) |
| **Impact (I)** | 5 (критическое - полный доступ к БД) |
| **Risk Score** | **15 (High)** |
| **Стратегия** | **Снизить** (Mitigate) |
| **Владелец** | Backend Developer |
| **Срок** | До миграции на PostgreSQL (Sprint 6) |
| **Критерии закрытия** | SQLAlchemy ORM используется для всех запросов<br>0 raw SQL queries или все через parameterized<br>SAST (Bandit) проходит без SQL injection warnings<br>SQLMap тестирование без findings |

### RISK-004: Утечка чувствительных данных в логах
**Описание**: Пароли, токены, PII могут попасть в логи и стать доступны злоумышленникам.

| Параметр | Значение |
|---|---|
| **Связанная угроза** | I-F7 (STRIDE) |
| **Связанные потоки** | F7 (DFD) |
| **Связанные NFR** | NFR-004 (Безопасность), NFR-006 (Логирование) |
| **Likelihood (L)** | 4 (высокая - без log sanitization) |
| **Impact (I)** | 4 (высокое - компрометация credentials) |
| **Risk Score** | **16 (High)** |
| **Стратегия** | **Снизить** (Mitigate) |
| **Владелец** | Security Engineer |
| **Срок** | Sprint 4 (1 неделя) |
| **Критерии закрытия** | Log sanitization middleware внедрен<br>Structured logging с whitelist полей<br>Automated PII detection в CI (detect-secrets)<br>Manual log review подтверждает отсутствие PII |

| **Likelihood (L)** | 3 (средняя - при инциденте критично) |
| **Impact (I)** | 3 (среднее - затруднен incident response) |
| **Risk Score** | **9 (Medium)** |
| **Стратегия** | **Снизить** (Mitigate) |

- **High (10-16)**: 6 рисков (RISK-002, 003, 004, 006, 007, 008)

- **Low (1-4)**: 0 рисков

## Связь с STRIDE и DFD

Все риски связаны с угрозами STRIDE и потоками данных DFD:
- **RISK-001, 006** → S-F1, E-F10 (Spoofing, Elevation of Privilege)
- **RISK-002** → D-F1 (Denial of Service)
- **RISK-003** → I-F5 (Information Disclosure)
- **RISK-004** → I-F7 (Information Disclosure через логи)
- **RISK-005** → R-F7 (Repudiation)
- **RISK-007** → Операционный риск (Data Zone)
- **RISK-008** → Общий риск безопасности

## Метрики отслеживания

1. **Reduction Rate**: % закрытых high/critical рисков за sprint
2. **Time to Remediate**: Среднее время закрытия риска
3. **Coverage**: % NFR покрытых рисками (текущий: 100%)
4. **Compliance**: % рисков с критериями закрытия, соответствующими NFR

**Цель**: Risk Score снизить до ≤ 5 (Medium/Low) для всех рисков к Production Launch.
